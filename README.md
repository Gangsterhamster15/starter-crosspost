# Кросспостинг: Telegram → VK и MAX

Публикуете пост в Telegram-канале как обычно. Раз в ~5 минут GitHub Actions забирает новые посты и публикует их в VK и MAX (текст, форматирование, фото, видео, альбомы).

## Настройка

### 1. Репозиторий
Создайте **приватный** репозиторий на GitHub и загрузите в него все файлы из этого архива (включая папку `.github`).

### 2. Telegram
- Бот из @BotFather должен быть **администратором канала** (достаточно права читать сообщения).
- У бота **не должно быть webhook** и он не должен использоваться другими сервисами автопостинга или модерации, которые тоже читают обновления. Лучше создать отдельного бота под это.
- `TG_BOT_TOKEN` — токен бота.
- `TG_CHANNEL_ID` (необязательно) — id канала вида `-1001234567890`. Если бот состоит только в одном канале, можно не задавать.

- `TG_ADMIN_IDS` — Telegram-id людей, которым разрешено пересылать боту старые посты для публикации (через запятую). Свой id можно узнать у @userinfobot.

### 3. VK
- `VK_GROUP_ID` — числовой id сообщества (без минуса).
- `VK_TOKEN` — токен с правами на стену, фото и видео. Для загрузки видео чаще всего нужен **пользовательский токен** администратора сообщества (scope: `wall,photos,video,offline`). Токен сообщества подойдёт для текста и фото, а видео с ним может не загрузиться.

### 4. MAX
- `MAX_TOKEN` — токен бота MAX.
- `MAX_CHAT_ID` — id канала в MAX. Бот должен быть добавлен в канал администратором. Список чатов бота можно посмотреть запросом `GET https://platform-api.max.ru/chats` с заголовком `Authorization: <токен>`.

### 5. Секреты
В репозитории: Settings → Secrets and variables → Actions → New repository secret. Добавьте все переменные из списка выше. Токены нигде, кроме секретов, хранить не нужно.

### 6. Проверка
1. Опубликуйте тестовый пост в канале.
2. Actions → Crosspost → Run workflow → отметьте **dry_run**. В логе будет видно, что скрипт увидел и как преобразовал текст. Тестовый прогон ничего не публикует и не «съедает» пост.
3. Запустите без dry_run и проверьте VK и MAX.

## Как преобразуется текст
- **MAX:** жирный, курсив, код и ссылки-слова сохраняются. Подчёркивание и зачёркивание пропадают.
- **VK:** разметки нет, поэтому ссылка, вшитая в слово, превращается в `слово (https://…)`. Фразы вроде «по ссылке» остаются понятными, потому что адрес идёт сразу за словом. Если нужен другой формат, правится функция `to_vk_text`.
- **Ссылки без `https://`:** в видимом тексте адрес показывается без `https://` (в MAX ссылка при этом кликабельна и ведёт на полный адрес). В VK адрес остаётся обычным текстом, и VK сам делает его ссылкой. Обычно это работает для популярных доменов, но если какой-то адрес не стал кликабельным, отключите сокращение: в файле workflow поменяйте `STRIP_SCHEME: "1"` на `"0"`.
- **Подписи:** в конце каждого поста ставится подпись своя для площадки. В MAX это «STARTER: Telegram • VK • MAX» со вшитыми ссылками на все три страницы, в VK это «STARTER: t.me/starter_live • max.ru/id7839494297_biz» обычным текстом (VK сам превратит адреса в ссылки). Если в исходном посте в Telegram последней строкой уже стоит подпись, начинающаяся с «STARTER:», скрипт её убирает и ставит нужную. Если подписи в посте нет, она просто добавляется. Адреса и тексты подписей лежат в начале `crosspost.py`, в блоке «Подписи под постами».
- **Старые и пропущенные посты (пересылка боту):** бот не видит историю канала, только новые посты за последние 24 часа. Чтобы опубликовать старый пост в VK и MAX, **перешлите его боту в личные сообщения**. Работает с текстом, фото, видео и альбомами, подпись подставится своя для каждой площадки. Бот ответит в личку, когда пост опубликован. Принимаются только пересылки от людей из секрета `TG_ADMIN_IDS` (Telegram-id через запятую), остальные сообщения игнорируются. Скрипт не отслеживает дубли: если переслать уже опубликованный пост, он выйдет повторно. Обычные сообщения боту (не пересылки) тоже игнорируются.
- **Большие видео:** Bot API Telegram отдаёт файлы только до 20 МБ. Если видео больше, оно не копируется, а в конец текста добавляется ссылка на оригинальный пост в Telegram.
- **Альбомы** склеиваются в один пост. Скрипт ждёт 90 секунд после последней части, поэтому альбом может уйти на следующем запуске.

## Ограничения
- Правка и удаление поста в Telegram не переносятся в VK и MAX.
- Если публикация в одну из сетей упала, пост повторно не отправляется (чтобы не было дублей в другой сети). Workflow завершится с ошибкой, и GitHub пришлёт письмо.
- Telegram хранит необработанные посты 24 часа. Если Actions не запускались дольше, посты потеряются.
- GitHub отключает расписание в репозитории без активности 60 дней. Если вдруг перестало работать, зайдите в Actions и включите workflow заново.
- Запуск по расписанию в GitHub может опаздывать на несколько минут, особенно в часы нагрузки.
